## 7.1 Профиль

- **Пароль**: нужен текущий пароль; после смены все остальные сессии завершаются.
- **Почта и логин**: смена тоже требует текущий пароль; проверка уникальности.
- **Язык и тема** хранятся в профиле (`users.locale` уже есть, добавить `users.theme`). Браузер берёт их после входа, localStorage остаётся только для экрана входа.
- **Активные сессии**: устройство (по User-Agent), IP, время входа и последней активности. Можно завершить одну сессию или все, кроме текущей (поля `sessions.ip/user_agent/last_seen_at` уже есть).
- **Steam-профиль**: ссылка разбирается тем же `resolveSteamProfile`, сохраняется steamID64. На странице модераторов сервера появляется кнопка «Добавить меня» (нужно право `server.moderators`).
- Аудит: `profile.password_change`, `profile.email_change`, `session.revoke`.
- Миграция: `users.theme`, `users.steam_id64`, `users.steam_name`.

## 7.2 Пользователи и доступ к серверам

### Модель

- Глобальная роль: `administrator` | `user`.
- Роль на сервере (`server_members`: server_id, user_id, role): `owner`, `manager`, `moderator`, `viewer`. Набор прав тот же, что сейчас у глобальных ролей. `owner` = `manager` + удаление сервера + управление участниками.
- Администратор видит и может всё. Пользователь видит только серверы, где он участник.
- Миграция существующих данных: администраторы остаются администраторами. Пользователи с ролями manager/moderator/viewer становятся `user` и получают ту же роль на всех существующих серверах. Владельцем существующих серверов становится первый администратор.

### Лимиты (задаёт администратор)

- `user_quotas`: максимум серверов, суммарная RAM (МБ), суммарные CPU, место под бекапы (МБ).
- Для новых пользователей лимит по умолчанию 0: сервер создать нельзя, пока администратор не выдаст лимит. Значение по умолчанию задаётся в настройках.
- Проверка лимита при создании сервера и при смене RAM/CPU — в той же транзакции, под advisory lock на пользователя (иначе два параллельных запроса пробьют лимит).
- Лимит считается по владельцу сервера, а не по участникам.
- Если сумма лимитов всех пользователей больше ресурсов VPS, администратор видит предупреждение (переподписка разрешена, но видна).
- Порты по-прежнему выделяет общий аллокатор; выбрать произвольный порт пользователь не может.

### Аккаунты

- Самостоятельной регистрации нет. Администратор создаёт пользователя, панель выдаёт одноразовую ссылку-приглашение (72 ч). По ней пользователь сам задаёт пароль. Почтовый сервер не нужен.
- Администратор может: отключить пользователя (сессии гаснут сразу), сбросить пароль (новая ссылка), поменять лимит, передать сервер другому владельцу.
- Удалить пользователя, который владеет серверами, нельзя, пока серверы не переданы или не удалены.

### Участники сервера

- Владелец добавляет участника по логину или почте и выбирает роль. Владельца сменить может только администратор, или сам владелец, передав сервер.
- Участник может сам выйти с сервера.

### Безопасность (главный риск среза — IDOR)

- Одна функция проверки `canOnServer(user, serverId, permission)` используется во всех маршрутах `/api/servers/:id/*`, в WebSocket-подписках, в выдаче консоли, бекапов и файлов.
- Если сервер существует, но пользователь не участник, ответ **404**, а не 403: существование чужого сервера не раскрывается.
- Списки (`/api/servers`, `/api/metrics`, WS-подписка `*`) фильтруются по участию.
- `logon token` уникален глобально, но ошибка «токен уже используется» не говорит, на каком сервере.
- Тесты: для каждого маршрута — пользователь без доступа получает 404, участник с ролью ниже нужной получает 403.

### Журнал аудита (UI)

- Администратор видит весь журнал. Владелец видит записи по своим серверам. Фильтры: пользователь, действие, сервер, период.

## 7.3 Замена server_packages

Загрузка уже перезаписывает файлы. Добавляется:

- **История**: перед заменой текущая пара `.sii` + `.dat` уходит в `packages-history/<время>/` в каталоге сервера. Хранятся последние 5 версий. Новые операции агента входят в закрытый список: список версий, восстановить версию.
- **Карточка пакетов**: размер, sha256, дата и кто загрузил. Кнопки «Скачать текущие» и «Откатить».
- **Проверка**: `.sii` должен разбираться нашим SII-парсером. Какие ещё признаки проверять, решим по настоящим файлам из `server-files-ets2/ats`, без выдуманных полей.
- **Работающий сервер**: файлы заменяются на диске, сервер получает пометку «нужен перезапуск» (баннер уже есть) с кнопкой «Перезапустить сейчас». Что DS читает пакеты только при старте, проверить на VPS.
- Загрузка и откат — отдельное право `server.files`, запись в аудит.

## 7.4 Бекапы

### Что входит в бекап сервера

- Файлы: `server_packages.sii/.dat`, `server_config.sii`, данные из домашнего каталога DS (`/srv/home`). Что там действительно нужно для восстановления, проверить на VPS.
- Состояние из БД: активная версия конфига, модераторы, настройки сервера.
- **Не входят**: файлы игры (переустанавливаются через SteamCMD) и секреты (logon token, пароль сессии). При восстановлении остаются текущие секреты сервера.
- Формат: `tar.gz` + `manifest.json` (версия формата, игра, версия игры, id сервера, sha256 файлов, версия панели).

### Операции

- Создать (фоновая задача). На работающем сервере тоже можно: файлы маленькие, а `server_config.sii` DS перезаписывает только при старте.
- Восстановить (фоновая задача): остановить сервер → сделать страховочный бекап «перед восстановлением» → распаковать → вернуть конфиг и модераторов → запустить, если сервер работал.
- Скачать (потоковая отдача).
- Загрузить свой архив и восстановить из него. Проверяется манифест, игра и sha256. Распаковка строго внутри каталога сервера: запрещены `..`, абсолютные пути, ссылки и устройства. Это главный риск среза.
- Удалить (с подтверждением).
- Ротация: хранится последних N на сервер (по умолчанию 7) и в пределах лимита места пользователя.
- Хранилище: `/var/lib/truckpanel/backups/<serverId>/`. Архивы пишет и читает агент; панель хранит метаданные в `server_backups`.

### Бекап самой панели

- База панели (`pg_dump`) и `.env` с ключами — только администратору. Команды установщика `install.sh backup` / `install.sh restore` плюс ежедневный запуск по таймеру systemd. В архив пользовательских серверов это не входит.

## 7.5 Расписание

- Таблица `scheduled_tasks`: сервер, действие (`restart`, `update`, `backup`, `start`, `stop`), расписание, часовой пояс, включено ли, последний и следующий запуск, результат.
- В UI простые варианты: «каждый день в ЧЧ:ММ», «по дням недели», «каждые N часов». Внутри — cron-выражение; библиотеку выбрать и проверить при реализации.
- Исполнитель внутри панели проверяет расписание раз в 30 с и берёт задания через `FOR UPDATE SKIP LOCKED`. Действие идёт через `ServerManager`, то есть с той же сериализацией. Если сервер занят другой задачей, запуск пропускается с пометкой «занят», без очереди.
- Пропущенные во время простоя запуски не догоняются; выполняется следующий по расписанию.
- **Обновление игры**: если вышла новая сборка, выполняется остановка → обновление → запуск; если нет, ничего не происходит. Как узнать номер последней сборки через SteamCMD — исследовать (не выдумывать).
- **Предупреждение игроков**: DS не принимает команды из консоли, поэтому написать в игровой чат нельзя. Вместо этого можно отправить сообщение в Discord за N минут (после фазы 6).
- **Автоперезапуск при падении** (из исходного плана): переключатель на сервере. Не больше 3 попыток за 10 минут, потом статус ERROR и запись в аудит.
- Ограничение для пользователей: интервал не чаще 15 минут, не больше 10 заданий на сервер.

## Что проверить на VPS до реализации

1. Читает ли DS `server_packages` только при старте (для 7.3).
2. Что в `/srv/home` нужно для восстановления сервера (для 7.4).
3. Как через SteamCMD получить номер последней сборки и сравнить с установленной (для 7.5).

## Тесты

- 7.1: смена пароля гасит чужие сессии, нужен текущий пароль, завершение отдельной сессии.
- 7.2: матрица IDOR (404/403) по всем маршрутам и WS-каналам; гонка лимита (два параллельных создания); миграция ролей.
- 7.3: история и ротация 5 версий, откат, отказ на невалидный `.sii`.
- 7.4: распаковка вредных архивов (`..`, абсолютный путь, symlink, hardlink, устройство); восстановление чужого бекапа и бекапа другой игры; ротация и лимит места; секреты не попадают в архив.
- 7.5: расчёт следующего запуска с часовым поясом; пропуск при занятом сервере; без догоняющих запусков; лимит автоперезапуска.
